Сессия 85: лаунчер показывает сетевой адрес, кэш CSS, мелкие правки

Жалобы: «start_game.bat запускает 127.0.0.1, а не 192.168.1.101» и
«по мобильной адаптации ничего не поменялось».

1. ЛАУНЧЕР: ПРАВИЛЬНЫЙ АДРЕС В БРАУЗЕРЕ И ВЫВОДЕ
Было жёстко http://127.0.0.1:8002 в трёх местах. Теперь адрес считается из
GAME_BIND: для конкретного IP берётся он, для 0.0.0.0 — LAN-адрес машины
через новый scripts\lanip.ps1 (только 192.168.* / 10.*: VPN-туннели и
Hyper-V с телефона недоступны), для loopback — 127.0.0.1. Переменная
GAME_PUBLIC_HOST перекрывает всё. Проверено: печатает
[START] Text Game RPG: http://192.168.1.101:8002

2. МОБИЛЬНЫЕ СТИЛИ НЕ ПРИМЕНЯЛИСЬ — ЭТО БЫЛ КЭШ
Правки CSS были на месте, но /static отдавался БЕЗ Cache-Control, и
мобильный браузер по эвристике держал старую копию. Добавлен
_NoStaleStatic: Cache-Control: no-cache (файлы перепроверяются по ETag,
а не перекачиваются целиком).

3. ЧЕКЕР БАТНИКОВ: ЛОЖНОЕ СРАБАТЫВАНИЕ
`echo %GAME_BIND% | findstr ...` — вывод в pipe, а не сообщение игроку;
регулярка считала это приглашением «запустись на 0.0.0.0». Теперь строки
с pipe исключены.

Тесты обновлены под новый вид веток; 1118 passed.

Про dsh: это отдельный продукт, его код не в этом репозитории. Он уже
слушает 192.168.1.101:3080, но отвечает 401 «reopen the URL printed by
dsh web» — нужен токен, который dsh печатает при старте. Лечится
повторным запуском dsh и открытием полного URL из его вывода.
