## 🎯 ЦЕЛЬ ПРОЕКТА

Живая текстовая RPG с ИИ-рассказчиком: игрок пишет действия на естественном языке, LLM (локальная
llama.cpp или облако) генерирует ответ, мир живёт, **ничего не забывается** (гибридная память +
карточки сущностей). Веб-приложение: FastAPI + vanilla JS SPA, состояния в SQLite, векторы в ChromaDB.

**Сменный рассказчик:** персону повествователя (промпт) можно менять/создавать/править/удалять.
**Сменные провайдеры:** основная модель (llama.cpp / Ollama / OpenAI-совместимый), эмбеддинги,
реранкер и TTS — глобально в `.env`/админке и per-world в UI.

> ⛔ Движок механики — НЕ игровой смысл. Он лишь ОБСЛУЖИВАЕТ рассказчика.

## 🏛 ТРИ ЗАКОНА АРХИТЕКТУРЫ (нарушение = доработка не принимается)

Любая механика и любая плановая доработка проходят эти три фильтра. Не вписывается — переформулируй
так, чтобы вписалась, либо не делай. Планировать доработки без трёх законов НЕЛЬЗЯ.

### 1️⃣ ТОЛЬКО универсальные механики (для всех жанров и тем)
- Код хранит ОБЩИЕ абстракции: состояния, HP/MP/золото/уровень/статы, инвентарь+вес, эффекты, флаги,
  время/погода, фракции/репутацию, квесты/цепочки, магазины/торговлю, крафт/станции,
  компаньонов/врагов, способности.
- Вшитые сущности (расы/классы/профессии/навыки) — лишь **справочники-подсказки**; творческие
  появляются через `race_change{name,bonus,passive}` / `class{name,skill}` / `profession{name,buff}`.
- НЕЛЬЗЯ зашивать «это фэнтези/это ретро/это техно» в логику движка как жанровый закон. Исключение
  `_is_modern_world` — осознанное и минимальное (только контекст старта роли), с комментарием «почему».

### 2️⃣ Общие базовые возможности для удобства, отображения и базовой логики
- Код даёт инфраструктуру: `format_state`, справки-агрегаторы (`total_sell_value`, `can_craft`,
  `/economy` `/stats` `/map` `/inventory`), парсинг кривых ответов модели, валидацию.
- Это только чтение/отображение/проверка, никогда — принятие решений за мастера.

### 3️⃣ Код только ПРОВЕРЯЕТ возможность; мастер-рассказчик решает ВСЁ
- Код — «судья возможностей»: нет золота/материалов/станции/профессии/веса → отказ с объяснением.
  Он не отказывает «потому что не по жанру».
- Прогресс и суть персонажа — творчество рассказчика: профессия/класс/титул/уровень/статы меняются
  ТОЛЬКО директивами (правило 19 промпта); авто-прокачки по XP/очкам/счётчикам НЕТ.
- Рассказчик всегда может разрешить действие или дофантазировать мир — код не блокирует.
- **Тест для любой доработки**: *«Код решает за мастера?»* Если ДА → переводи задачу в «проверку
  возможности» (валидируй — решение оставляет мастер).

Это **канон формулировок**: в `README.md` («🎯 Философия дизайна (три закона игры)») они повторены
сжато, и заголовки обязаны совпадать — следит `test_three_laws_identical_in_docs` (C11).

## ⚠️ ЖЁСТКИЕ ПРАВИЛА (нарушение = сломанный проект)

1. **НЕ трогать запущенный llama.cpp** на `127.0.0.1:8080` (модель любая — какая загружена;
   реальное окно контекста игра детектит сама, `DETECT_MODEL_CONTEXT`). Если его нет — молча не запускаем, сообщаем пользователю.
2. **НЕ трогать чужую ChromaDB на `127.0.0.1:8000`** (порт занят другим проектом этой машины). У игры **свой**
   экземпляр: порт **8001**, venv `data/chroma-venv`, данные `data/chroma`, коллекция `text_game_memory`.
3. **Секреты** (`EMBEDDING_API_KEY`, `MAIN_API_KEY`, `RERANK_API_KEY` в `.env`) — **никогда не выводить**
   значение ключа в консоль/логи/ответы: показывать `***`/маску `••••••••` (`KEY_MASK` в `config.py`,
   маскирует `routers/core.py::_mask_provider`). Наружу (в `/api/*`, в экспорт, в дамп) ключ уходит
   только маскированным: `GET /api/worlds/{id}` и ответ `POST .../providers` отдают снимок через
   `_masked_provider_settings` + `_safe_world_row` (маскирует и вложенный JSON
   `world.provider_settings` — иначе ключ утекал «боковой дверью»), а `db.world_dump` дополнительно
   **вырезает** `api_key` из JSON-дампа — см. правило 15.
4. **Суммарный промпт — много меньше контекста модели.** Стандарт `.env`: `MAX_TOKENS=2000` (вывод)
   и `CONTEXT_TOKENS=32768` — под облачные модели. Бюджеты памяти: `RECENT_TOKEN_BUDGET=2600`,
   `SUMMARY_TOKEN_BUDGET=700`, `RAG_MEMORY_K=4`, `RAG_CANDIDATES=20`. **Не превышать n_ctx РЕАЛЬНОЙ
   модели**: локальная llama.cpp = 8192 → уменьшать `context_tokens` per-world (ползунок «Размер
   контекста») или в `.env`. Оценку токенов делать `config.est_tokens` (len/3.2), на точность не
   полагаться.
5. **После любого изменения `backend/*.py` — перезапуск сервера ОБЯЗАТЕЛЕН**: убить процесс на 8002
   (`netstat -ano | grep :8002` → `taskkill //F //PID <pid>`), затем
   `python -X utf8 -m uvicorn backend.app:app --host 127.0.0.1 --port 8002` (из корня, с `-X utf8`).
   Тот же адрес обязателен и в `start_game.bat` — **наружу (0.0.0.0) не слушать**: авторизации в игре
   нет, а в `.env` живые ключи. Защищает и сам launcher: чужой `GAME_BIND` без `GAME_BIND_CONFIRM=1`
   = отказ запуска; `/api/admin/settings` отвечает только с localhost (`ADMIN_ALLOW_LAN` —
   сознательное открытие, самой админкой не включается); «дорогие» LLM/сетевые эндпоинты под
   rate-limit'ом, чужому адресу лимиты режутся в `REMOTE_FACTOR` раз.
6. Фронтенд (`frontend/`) отдаётся статикой через `StaticFiles` mount `/static` — правки видны после
   refresh, перезапуск не нужен. Оба HTML-роута (`/` и `/admin`, `routers/system.py`) отдаются с
   `Cache-Control: no-store`; `app.js`/`style.css` идут с ревалидацией по `ETag` — при «поведённом»
   фронте всё же делай hard refresh. ⚠ Правки Python — перезапуск сервера, правки фронтенда — нет.
7. **SQLite-схема** (`data/game.db`) — миграции только идемпотентные: добавить
   `CREATE TABLE IF NOT EXISTS` в `backend/db.py::_init_schema`. Не удалять БД без спроса.
   Идемпотентная **само-исцеляющая чистка** допустима и уже есть: `db.prune_orphan_rows()` при старте
   убирает строки связанных таблиц у несуществующих миров (`worlds.id` — AUTOINCREMENT, и после
   VACUUM/импорта дампа id может достаться новому миру, который «унаследует» карточки/лор удалённого).
   `DELETE /api/worlds/{id}` чистит **все** связанные таблицы (events/saves/turn_snapshots/entities/
   lore/graph_nodes/graph_edges) и начинается с чистки векторов в Chroma: при её отказе — 503, мир НЕ
   удалён (иначе SQLite-строки ушли, а векторы осиротели). Тот же класс с другой стороны закрывает
   `memory.sweep_orphan_vectors()` при старте (инвариант 31).
8. **Эмбеддинги/реранкер — облачные RouterAI**: модель `qwen/qwen3-embedding-8b`
   (4096-dim, префиксы `"Passage: "` для документов, `"Query: "` для запросов), реранкер
   `voyageai/rerank-2.5` через `/v1/rerank`. Полный оффлайн без ключей даёт провайдер `local`
   (FastEmbed `paraphrase-multilingual-MiniLM-L12-v2`, 384-dim, кэш `data/fastembed`).
9. **Фоновые задачи** (память/карточки/сводки/агенты) — асинхронные, **не блокируют ответ игроку**.
   LLM-проходы — `bg.submit(name, factory, priority=…, world_id=…)`; короткие «огонь-и-забыл» —
   **`bg.spawn(coro, name=…)`**, а НЕ `asyncio.get_event_loop().create_task(...)`: asyncio хранит
   задачи слабыми ссылками, и брошенную задачу мог собрать сборщик мусора посреди игры (симптом
   «карточка/индекс не появились, в логе ничего»). `get_event_loop()` устарел в 3.12 и ошибка в 3.13:
   в async-коде `get_running_loop()`, в тяжёлых синхронных вызовах — `asyncio.to_thread`. Очередь,
   приоритеты, барьеры перегенерации, «мир в ходу»/откат — `backend/bg.py` (`bg.submit`, `bg.spawn`,
   `bg.regen_block`, `bg.rewind_block`, `bg.turn_block`, `bg.player_turn`). Защита от повторов —
   busy-множества `_cards_busy`/`_judge_busy`/`_master_busy`/`_enemy_ai_busy`/`_event_busy`/
   `_vision_busy` в `backend/routers/core.py` (НЕ в app.py: там только сборка).
10. Все файлы — **UTF-8**; Python запускать c `-X utf8` (Windows cp1251 ломает кириллицу).
11. **Судья логики — фоновый** (LLM-as-a-Judge), как архивариус: НЕ синхронный, НЕ переписывает ответ,
    не «душит» креативность. Две задачи: (а) противоречие жёстким фактам (мёртвый NPC / флаг) →
    системное сообщение-«искажение реальности» (сюжетный поворот, ошибка ИИ = фича мира); (б)
    **согласованность биографии и роли** (раса/класс/профессия/навыки/уровень) → грубый конфликт
    даёт `corrections`, применяемые через движок директив. Глобальный выключатель
    `LOGIC_JUDGE_ENABLED` (.env/админка), per-world `gen_settings.logic_judge`, частота
    `LOGIC_JUDGE_INTERVAL`.
12. **Гарантия роли на старте**: `apply_character` контекстно-зависимый — для «современных»/реал/
    литрпг-миров (`_is_modern_world`) не форсирует фэнтезийный класс, ставит расу «Человек» и
    профессию «Безработный» при пустых полях; для фэнтези — класс по лучшему стату.
13. **Парсинг `game_engine({...})` текстом**: в tools-режиме модель иногда «выпевает» вызов вместо
    настоящего `tool_call` — `split_engine`/`find_engine_start` распознают `<<ENGINE>>`,
    `game_engine({...})` и голый JSON-блок, **в том числе вставленный в середину абзаца**, вырезая
    механику из видимого текста (единый сканер с балансировкой скобок, а не «от маркера до конца
    строки»). `engine_tail_hold` не даёт стриму показать обрывок маркера.
14. **Не глотать ошибки в фоне молча**: в любых фоновых/асинхронных задачах (память, карточки, сводки,
    судья логики, динамические события, TTS) избегать тихого `try/except: pass` — логировать через
    `logger` (модуль `textgame`) с `logger.exception(...)`/`logger.warning(...)` и контекстом
    (world_id, seq, действие), чтобы диагностика не терялась. То же к «тихим» `return None` на
    горячем пути. Отказ фонового агента пишется через `narrator._agent_quiet()` — это `log_once` с
    ключом (`агент`, `world`) и traceback-ом: молчание исключено, но и лог-шторм на каждом ходу тоже
    (агент живёт каждый ход, а при лежащей модели падает КАЖДЫЙ проход). `db.close()` пишет warning
    при незакрытом соединении/цикле (залоченный `game.db` на Windows), отказ rate-limit виден в
    журнале с ключом. Исключение — легальные фолбэки (RAG при выключенных эмбеддингах — ожидаемое
    поведение, а не ошибка; сама недоступность RAG логируется).
15. **Git и секреты (сессия 33)**: репозиторий `github.com/pL1uXa-AI/text_game_rpg` — **приватный**. В git НЕ попадают: `.env` и любые `.env.*` (живые ключи), вся папка `data/` (game.db, chroma, chroma-venv, tts, fastembed, backups, metrics.jsonl, logs/), логи, `nul`, кэши, `__pycache__`. В репозитории — код, документация, `plots/` и `.env.example` (шаблон без ключей). Перед каждым пушем проверять: `git diff --cached | grep -ciE "sk-[A-Za-z0-9]{12,}"` → **0**. JSON-дамп мира (`/export/json`) обязан быть без ключей (тест `test_world_dump_strips_api_keys`). Мусор рабочей копии (`.env.bak*`, `nul`, `server*.log`) не обещается навечно убранным: такие файлы могут появляться локально снова, и это не ошибка доков — `nul` плодит любое `>nul`/`> nul` в `.bat` (`start_game.bat`, `scripts/setup_env.bat`), а `server*.log` — ручной перезапуск сервера с перенаправлением вывода. **Рабочее дерево — не объект проверок**: тест `test_b1_trash_files_stay_out_of_git` сверяет **индекс git**, а не файлы на диске, и никогда не утверждает, что рабочее дерево чисто; за правдой о дереве следят `tests/test_session57_worktree_trash.py` (канон мусора покрыт `.gitignore`). **Удалять такие файлы — только по явному разрешению владельца**: это его рабочие файлы и его логи, а `nul` на Windows снимается лишь `del \\?\D:\...\nul` — обычный `rm`/`del` его не видит.

## 🧠 АРХИТЕКТУРА (понимание проекта)

### Поток одного хода игрока
```
POST /api/worlds/{id}/action[/stream]
  → db.add_event(player)
  → 🕐 начало хода (routers/core.py): tick_effects (HP/MP ×стаки, turns−1, «⏳ … осталось N ходов»)
    + tick_needs_mental + tick_world_timers + tick_time (авто-часы: утро→день→вечер→ночь); всё — в
    tick_msgs: уходят системками в чат И в контекст рассказчика («[Начало хода] …»); при
    перегенерации тикаются только после отката к снапшоту
  → narrator.retrieve_memory()          # RAG: Chroma → гибрид BM25 → rerank
  → narrator.select_relevant_entities() # карточки сущностей (приоритетная выдача)
  → _recent_block(exclude_ids=…)        # недавняя ИСТОРИЯ без событий текущего хода
    # действие уже записано в БД и ОДНОВРЕМЕННО идёт в [ДЕЙСТВИЕ ИГРОКА]; без фильтра модель читала
    # его дважды (дубль съедал recent_token_budget и провоцировал копировать свою формулировку).
    # При ↻ отсекаются и прежнее действие, и replaced_ids.
    # ИНВАРИАНТ: любой новый блок промпта из «своего» события хода обязан попасть в exclude_ids.
  → narrator.build_messages() → (messages, meta)  # system + сводки + лор + RAG + карточки + recent
  → llm.stream_chat() / llm.complete()  # llama.cpp или облако
  → narrator.split_engine()             # вырезает <<ENGINE>>{...} из ответа
  → narrator.apply_directives()         # применяет механику к setting; возвращает системные сообщения
  → если directives["roll"]: roll_expr() + narrate_roll() (второй LLM-проход описывает результат)
    # roll_expr клампит ввод: count ≤ 100, 2 ≤ sides ≤ 1000, |mod| ≤ 1000; «ноль кубиков»/d0/d1/
    #   нераспознанное → фолбэк d20 + log.warning, ход НЕ падает (без 500).
    # roll_outcome судит по ФАКТУ броска, а не по написанию/итому: nat-1 — это грань из res["rolls"]
    #   (одинокий кубик, выпала 1 — крит-провал даже с mod +5); форма кубика читается из той же
    #   регулярки, что распознавание (`d20` = `1d20` = `D20+3`); планка «провал на 10+ хуже dc» —
    #   только у одиночного d20.
  → db.add_event(narrator [+ dice + system]) → db.update_world(setting)   — одной транзакцией
  → narrator.ensure_knowledge_cards()   # карточки знаний (раса/класс/профессия/навык/эффект) инлайн
  → TTS-озвучка (если включена): событию tts_status=1, фоновый tts.ensure_event_audio (кэш + файл)
  → 📈 метрики хода (metrics.record) — в памятный БУФЕР, диск на горячем пути не трогается;
    data/metrics.jsonl дописывается ПАЧКАМИ (по объёму или «разрядкой» по возрасту), остаток — finally
  → фоновые задачи: index_exchange, summarize_and_compress, update_entity_cards, index_entities
  → ⚖️ судья логики (по интервалу ходов) · 🌍 динамическое событие (по шансу на ход, event_chance)
    · 🤖 автономный мастер (по интервалу) · ⚔️ боевой ИИ врагов (пока есть живые враги)
    # ВСЕ фоновые агенты (судья/мастер/боевой ИИ/видение) зовут свой LLM-проход на ПЕРЕЧИТАННОМ из БД
    # состоянии `s`, а не на снимке хода `agents_setting` (иначе вердикт по фактам прошлого хода =
    # ложные «искажения реальности»). Знак `…` в их сигнатурах = `action, reply` (последний обмен),
    # а НЕ состояние: параметр `setting` у этих агентов — остаток до-А4 эпохи, в расчёте не участвует.
    # Динамическое событие — единственная задача, которой мир вообще не передаётся: она перечитывает
    # его сама — `_maybe_dynamic_event(world_id)` (один аргумент; правки строки дока и подписи
    # синхронны — сторожит tests/test_session68_dynamic_event_signature.py).
```

### Директивы `<<ENGINE>>` / function calling (механика через LLM)
Механика передаётся двумя способами, выбирается автоматически:
- **tools (function calling)** — облачные `main_provider=openai_compat` (RouterAI и др.): сервер шлёт
  инструмент `game_engine` (`narrator.py::GAME_ENGINE_TOOL`), директивы приходят как `tool_calls`
  (JSON аргументов). В контекст не попадают `<<ENGINE>>` — маркер не появляется в выводе (фильтр
  строк в `build_system_prompt` при use_tools).
- **промпт-формат `<<ENGINE>>`** — локальные llamacpp/ollama: модель пишет маркер по правилам промпта.
- Принудительный фолбэк-аудит: если tools-режим дал текст без механики, а действие её явно требует
  (`narrator.mech_trigger`), выполняется компактный проход с `tool_choice:required` → JSON дельт на
  основе текущего состояния + последнего обмена (`narrator.audit_messages`). Сбор вызовов —
  `llm.stream_chat/complete(…, tool_calls_out=…)`; `narrator.parse_tool_args` нормализует вложенные
  JSON-строки и «голые» дельты.
- Нормализация типов (`str` вместо `dict`, числовой `id` → строка) — `backend/directives.py`
  (Pydantic-схемы директив): `narrator.normalize_directives` делегирует туда; семантика закреплена
  золотым корпус-тестом `tests/test_directives_schemas.py`. Фолбэк при невалидном JSON —
  `_fallback_parse`.
- Применяются через **«Цепочку обязанностей»** (`backend/mechanics.py`): вместо одной гигантской
  `apply_directives` — обработчики `DirectiveHandler` по группам: `PlayerHandler` (hp/mp/gold/xp/
  stats/actions + уровень), `IdentityHandler` (раса/класс/ранг/эволюция/мультикласс/профессия),
  `SkillHandler` (навыки/титулы/репутация), `EffectHandler`, `ItemHandler`, `EconomyHandler`,
  `CraftHandler`, `CompanionHandler`, `EnemyHandler`, `QuestHandler`, `NpcHandler`, `FactionHandler`
  (фракции и связи), `LocationHandler` (карта/перемещение), `WorldHandler`
  (флаги/время/погода/game_over), `PlotDeviationHandler`. Все собраны в `DIRECTIVE_CHAIN`; каждое
  звено владеет непересекающимся набором ключей и обрабатывает только свои. **Новая директива = новый
  обработчик, а не правка монолита**; сбой звена изолирован try/except и не роняет ход; порядок
  сообщений сохранён.

агентов и в UI не попадает, а `PlotDeviationHandler` возвращает ПУСТОЙ список сообщений — строка «мир
отходит от канвы сюжета» в чате выдала бы существование заранее написанного сценария и ломала бы
иллюзию живого мира изнутри.
### Фоновые агенты (все идут через `bg.submit` после хода, ответу игроку не блокируют)
- **⚔️ Боевой ИИ врагов** — тактический агент, дающий живым врагам (`hp>0` в `setting.enemies`)
  собственный ход; запускается после каждого хода, как судья/мастер.
  `narrator._living_enemies(setting)` → список `[(id, enemy)]`, сортировка по убыванию `dmg` (кто
  опасный — решает первым) → `narrator.enemy_ai_messages` / `generate_enemy_ai(...)`
  (`max_tokens=260`; по живым врагам, состоянию игрока HP/статы/уровень через `effective_stats` и
  последнему обмену) выбирает ОДНО решение: `attack` (преследовать), `guard` (оборона/дистанция),
  `retreat`, `negotiate`, `trap`; JSON `{enemy, mode, note, directives}`.
  `narrator._apply_enemy_ai(setting, eid, mode, directives)` применяет решение **без нанесения урона
  игроку** (урон ведёт рассказчик в своём ходе — правило 9/9а, чтобы не задваивать): `retreat` убирает
  врага (`enemy_remove`, «🏃 … отступает»), остальные пишут `enemy.ai = mode` (намерение-подсказка
  рассказчику на следующий ход) и применяют не-уроновые директивы (flag/npc/quest/add_item).
  Задача `routers/core::_maybe_enemy_ai(world_id, …)` (`_enemy_ai_busy`), интервал
  `ENEMY_AI_INTERVAL`, системка «⚔️ …» + индексация в память, выключатель `ENEMY_AI_ENABLED`.
- **🤖 Автономный «мастер»** — выводит игрока из тупика; запускается после каждого хода, вмешивается
  редко. Детекция застревания `narrator.master_stuck_reason(actions, active_quests, turns)` —
  детерминированная, без LLM: `repetition` — в последних ≤6 действиях ≥2 похожих (нормализация/
  стоп-слова + порог схожести, `_action_similar`/`_norm_words`); `drifting` — сыграно ≥15 ходов без
  единого активного квеста и ≥3 действий; при разнообразии и наличии квеста — `None` (мастер молчит).
  LLM-проход `narrator.generate_master_nudge(setting, reason, recent_text, lang, provider)` →
  `(текст, директива)`; `master_messages` (компактный промпт, `max_tokens=300`) просит ОДИН шаг (квест
  через `quest` / сюжетный поворот / слух / NPC-подсказку), не решать за игрока и не ломать лор.
  Задача `routers/core::_maybe_autonomous_master(world_id, …)` (`_master_busy`), интервал
  `AUTONOMOUS_MASTER_INTERVAL`, системка «🤖 Мастер: …» + `apply_directives` + индексация,
  выключатель `AUTONOMOUS_MASTER_ENABLED` (.env).
- **🌍 Динамическое событие** — `_maybe_dynamic_event(world_id)`, шанс `event_chance` на ход: случайный
  сюжетный поворот мира («🌍 …») + директивы. Единственная фоновая задача, которой снимок состояния хода
  НЕ передаётся (мир и `setting` она перечитывает из БД сама).
- **⚖️ Судья логики** — см. жёсткое правило 11; вердикт считает по перечитанному из БД состоянию.

### Динамическая сложность
Сила врагов и частота случайных событий подстраиваются под `player.level`, чтобы угроза не отставала
от прокачки и мир не деградировал в сторону лёгкости.
- `mechanics.dynamic_adversary_scale(player, difficulty, level=)` → множители `{hp, dmg, event}`: на
  уровне 1 все 1.0; дальше рост за каждый уровень зависит от сложности мира (`_DYNAMIC_SLOPES`:
  easy/normal/hardcore — хардкор растёт круче, лёгкая мягче); `event` растёт слабее (+5%/уровень).
- **Масштабирование `enemy_add` делает движок** (`EnemyHandler`): рассказчик задаёт БАЗОВУЮ HP/урон
  (нормальную для сеттинга/локации), множители накладывает движок — сила растёт детерминированно,
  даже если LLM не учла прокачку.
- `narrator.event_chance(turns_since, every_turns, level=)` — шанс растёт и с ходами, и с уровнем
  (`freq = 1 + (level-1)*0.05`); потолок **0.5** («никогда не гарантировано») сохранён.
- Подсказка рассказчику в `format_state`: «⚖️ Сложность: … → враги HP×…, dmg×…, события ×…» (задавать
  базовую силу); то же повторено в аудит-промпте боя.

### RPG-система
- **7 статов** (10 = средний человек): сила/ловкость/выносливость/интеллект/мудрость/харизма/удача —
  `player.stats`, штраф ниже 1 запрещён. Производные: `max_hp` от выносливости, `max_mp` от
  интеллекта+мудрости (`recalc_derived` не понижает максимумы старых сохранений).
  `effective_stats(p)` = база + моды эффектов (для проверок и формата состояния).
- **8 вшитых рас** (человек/эльф/дварф/орк/зверолюд/полудемон/драконид/нежить): бонусы статов +
  пассивка (эффект с `tag:race`); **6 вшитых классов** (Воин/Лучник/Маг/Вор/Жрец/Бард): при смене
  выдаётся стартовый навык; **9 вшитых профессий** (Кузнец/Алхимик/…/Книжник): постоянный бафф стата
  (`profession_buff`). Творческие — теми же директивами (`race_change {name, bonus, passive}` и т.д.).
  Ранги F<E<D<C<B<A<S<SS<SSS<Z<ZZ<ZZZ<G (`RANK_ORDER`), эволюция `class_evolve`,
  мультикласс `secondary_class`.
- **Профессии растут от действий — НО решает рассказчик**: `player.actions {действие: счётчик}` копятся
  директивой, но `check_profession_advance` в игровом конвейере (routers/core.py) больше НЕ
  вызывается (хелпер остался в `mechanics.py`) — решение о смене/изобретении профессии, класса,
  титула полностью на рассказчике (правило 19). Уровень/статы/репутация — тоже творческие.
- **Скрытые классы/расы/профессии/навыки** (правило 19): рассказчик может выдавать творческие сущности
  за особые цепочки действий/ритуалы/испытания без афиширования условий; системные сообщения хода
  становятся «условием получения» карточки (`meta.origin`).
- **Навыки**: `skills {имя: {rank, kind, desc, mp_cost}}` — активные/пассивные, с рангами.
- **Потребности/рассудок**: `player.needs` (голод/жажда/усталость) и `player.mental`
  (рассудок/стресс/мораль) — универсальные оси ресурсов со шкалами `{value, max, decay}`; тикают сами
  в начале хода, последствия ведёт мастер (закон 3, правило 31).
- **Экипировка**: у предметов `slot` + опц. `bonus {стат: +N}`; `equip`/`unequip` надевает/снимает
  (`player.equipped {слот: имя}`), бонусы входят в `effective_stats`; код отказывает двум предметам
  одного слота и при нехватке предмета; рассказчик даёт предметы с `slot` через `add_item`.
- **Эффекты**: постоянные/временные, стаки (урон×стаки в тике), моды к статам; тик в начале хода
  (`tick_effects`) — при перегенерации НЕ задваивается (снапшот). Тикают оба ресурса: HP
  (`damage`/`heal`) и MP (`mp_damage`/`mp_heal`). Временный эффект сообщает остаток каждый ход
  («⏳ … осталось N ходов») — раньше системка была только при уроне/лечении, и «тики молча» выглядели
  как «эффект не работает».

### Память — 5 слоёв (никто и ничто не забывается) + лор и состояние мира
1. **Краткосрочная**: последние несвёрнутые обмены в пределах бюджета (таблица `events`, роли
   player/narrator). **Бюджет per-world**: `world_recent_budget(world)` = `context_tokens −
   CONTEXT_OVERHEAD(2600) − max_tokens` (мин. 400). Размер контекста задаётся в настройках мира
   (ползунок «Размер контекста», `gen_settings.context_tokens`, по умолчанию `CONTEXT_TOKENS`); не
   превышать n_ctx модели (llama.cpp = 8192, облачные — до 32k+).
2. **Сводки**: при переполнении окна старые события сворачиваются LLM в 2–5 предложений
   (`summarize_and_compress`), роль `summary`, события помечаются `folded=1`. Игроку сводки не
   показываются нигде — это материал промпта.
3. **Векторная (RAG)**: ВСЕ обмены (`index_exchange`), сводки (`index_summary`), карточки
   (`index_entities`) и лор индексируются в свою ChromaDB (метаданные `world_id`!). Поиск
   `retrieve_memory`: эмбеддинг запроса → `chroma_client.query(where={"world_id": …})` → гибрид
   BM25+косинус (`embeddings.hybrid_rerank`, вес BM25 из `HYBRID_WEIGHT_BM25` .env/админка) →
   облачный реранкер → top-K. **Локальный оффлайн-эмбеддинг** — провайдер `local` (FastEmbed,
   `paraphrase-multilingual-MiniLM-L12-v2`, 384-dim, кэш `data/fastembed`). Так как Chroma держит
   одну размерность на коллекцию, коллекция выбирается **по фактической размерности входящих векторов**
   (`chroma_client.collection_name_for_dim`): облачный 4096 → `text_game_memory`, локальный 384 →
   `text_game_memory_local`; это устойчиво к per-world переключению провайдера. `delete_by_*` чистят из
   обеих коллекций. Порог косинуса для local ниже (`COSINE_THRESHOLD_LOCAL`, дефолт 0.20), т.к.
   fastembed даёт разрежённые близости; векторы нормируются при вставке и запросе.
4. **Карточки сущностей** (таблица `entities`): NPC, локации, фракции, квесты, предметы, события —
   каждый с `summary` (статус сейчас), `relationship` (отношения с игроком), `bio` (накопленная
   история), `meta` (JSON: alive/location/faction). После каждого хода LLM-архивариус обновляет их
   (`update_entity_cards`, JSON-ответ). В контекст попадают релевантные (`select_relevant_entities`:
   текущая локация, NPC рядом, активные квесты, явные упоминания в действии). `name` карточки — ВСЕГДА
   человекочитаемый, а не внутренний id: `memory.resolve_card_name` берёт имя из ответа архивариуса →
   из состояния мира (`card_name_from_setting`) → прежнее, и машинному id (`player`,
   `trail_to_outpost`) НЕ позволяет перетереть уже человекочитаемое имя; старые карточки чинит
   само-исцеление при старте (`memory.repair_machine_card_names` — правит только там, где имя ЗНАЕТ
   состояние мира).
5. **Карточки знаний** (таблица `entities`, kinds `race/class/profession/skill/effect/item`):
   детерминированно (без LLM) после каждого хода `ensure_knowledge_cards` фиксирует созданные
   расы/классы/профессии/навыки/эффекты и предметы инвентаря с их механикой
   (бонусы/пассивки/баффы/ранги/стаки/моды); на новых карточках из системных сообщений хода пишется
   `meta.origin` — **условие получения** («🎖 Изучен навык…», «⚒ Профессия: — → Кузнец…», «🎒 Получено:
   …») — чтобы рассказчик не противоречил себе; индексируются в Chroma (мета `entity_kind`) и
   выбираются `select_relevant_entities` (бонус приоритета за знание игроком).
6. **Лор мира (библия вселенной)** (таблица `lore`): большие статьи о мире (история, география,
   системы, фракции, термины, `tags`, `is_core` — якорные, `source` = theme/custom/user). Сидинг при
   создании мира: из темы-сюжета (статьи `lore_articles`/`lore_text` в файле сюжета, см.
   `backend/plots.py`) или из своего сюжета (`custom_lore` / `story_plots.lore`, разбор по
   `## Заголовок` → отдельные статьи). Чанкинг `_chunk_lore` (по абзацам/предложениям, ~550 токенов) +
   индексация в Chroma (`index_lore_entry`, kind=`lore`, мета `lore_id`/`title`, переиндексация при
   правке, `$and`-where). Отдача в промпт: `retrieve_lore` → якорные статьи (всегда, сжато) +
   RAG-чанки по действию игрока (`LORE_RAG_K`) + фолбэк свежими статьями при выключенном RAG; бюджет
   `LORE_TOKEN_BUDGET` (дефолт 900). Блок `[ЛОР МИРА — факты вселенной…]` в `build_messages`; правила
   27–29 в system prompt (26 — фракции): «не противоречь лору, не выдумывай канон; лор сжатый —
   достраивай в стиле». CRUD: `backend/routers/lore.py`, вкладка «Лор» в UI, поле лора в своём сюжете.
7. **Состояние мира** (`worlds.setting` JSON — всегда в system prompt через `format_state`). Здесь же
   `player.identity` — всегда заполненная биография персонажа «кто я» (имя/возраст/происхождение/
   занятие/положение): если игрок дал «Свой зацеп» — это он, иначе генерируется
   `narrator.generate_identity` по теме/лору при создании мира; показывается рассказчику каждый ход
   (`format_state`) и игроку в сайдбаре «Персонаж». **Богатый старт первой генерации**: доп. LLM-вызов
   `narrator.generate_character` заполняет при создании мира не только биографию, но и роль
   (раса/класс/профессия со стартовыми навыками/баффом/пассивкой через движок директив), уровень,
   распределённые характеристики (НЕ все 10), навыки, титулы и персонализированный инвентарь с
   описаниями — согласованные с миром/лором/биографией (бессмертный маг 900 лет не стартует
   новичком); применение — `narrator.apply_character`, при неудаче — фолбэк на `generate_identity`. В
   UI: блок «🧙 Персонаж» вкладки «Состояние» (после «Характеристик»): имя + полная биография +
   раса/класс/профессия/навыки/титулы/репутация/действия явными параметрами с описаниями; предметы
   инвентаря кликабельны — модалка с описанием (`showItem`). Стартовая локация — из
   `theme.start_location` (это КАНОН темы, а не зашитый персонаж).

### Формат промпта рассказчика (`build_system_prompt`)
Персона рассказчика (из `narrators.prompt` мира) → тема/жанр/сложность/перспектива/язык → правила
рассказчика (живой мир, логика, не решать за игрока) → описание формата `<<ENGINE>>` → текущее
состояние мира. Модификаторы из тем (сюжеты из `plots/`) и жанров (`GENRE_HINTS`, 33 шт,
`narrator_data.py`). **Ярусы промпта** (`gated_rules`/`trim_prompt`) выкладывают только правила живых
подсистем (≈ −30% токенов в мире без них); правила 9/9а/16 не выкладываются даже без врагов/эффектов
(риск задвоенного урона); ключуются НОМЕРАМИ правил — инвариант 10.

### Рассказчики (`narrators`, сменные персоны)
- Таблица `narrators(id, name UNIQUE, desc, prompt, is_preset, created_at, updated_at)`; 8 предустановленных сеются идемпотентно (`db.seed_narrators` — из стартового прохода
  `app.self_heal()`, а НЕ на импорте app.py; файлы `plots/narrators/*.js`). `GET /api/narrators`
  досеивает пустую таблицу сам (дешёвый `INSERT OR IGNORE`), чтобы каталог не пустовал в первые
  миллисекунды после запуска.
- **Пресеты живут файлами** в `plots/narrators/*.js` (чистый JSON: `name`/`desc`/`prompt`) — загрузчик
  `backend/narrators_loader.py` сканирует при старте и по mtime (`ensure_fresh` при
  GET /api/narrators); при изменении — пересид в БД `db.seed_narrators` идемпотентно по `name`.
  `narrator.NARRATOR_PRESETS` — это список из файлов.
- **Рекомендуемый рассказчик сюжета**: в JSON сюжета опц. поле `narrator` (имя пресета);
  `plots.py::_theme_from_plot` прокидывает его в тему (`theme["narrator"]`), `GET /api/themes`
  резолвит имя → `narrator_id` (по `db.list_narrators()`); фронт при выборе темы авто-подставляет его
  в селект (пользователь может сменить).
- `worlds.narrator_id` — рассказчик мира (NULL = дефолтный, первый). Персона попадает в
  `build_system_prompt(world, setting, persona=...)`, а также в `generate_opening` и `narrate_roll`.
  Смена — `POST /api/worlds/{id}/settings {narrator_id}`.
- CRUD: `GET/POST /api/narrators`, `PATCH/DELETE /api/narrators/{id}`. Удаление запрещено (409), если
  рассказчик используется миром.
- Архивариус карточек и сводки — отдельные системные персоны, рассказчиком НЕ управляются.

### Провайдеры (основная модель / эмбеддинги / реранкер / TTS)
- `config.py::PROVIDER_OPTIONS` — реестр: `main` (llamacpp|ollama|openai_compat), `embedding`
  (routerai|openai_compat|local|none), `rerank` (routerai|openai_compat|none), `tts`
  (piper|kokoro|edge|none). Это модульная константа, а не атрибут `Config`
  (`from .config import PROVIDER_OPTIONS`).
- Глобальные настройки — `.env` ИЛИ **админка** (`GET/POST /api/admin/settings`, страница `/admin`):
  таблица `admin_settings` (ключи в верхнем регистре, как env). Приоритет: env процесса → админка →
  .env. Пустое поле = сброс к .env; API-ключ при пустом поле не меняется; `invalidate_config()`
  сбрасывает кэш после сохранения. **Оба метода админки закрыты до localhost**
  (`ratelimit.require_local`; чужой адрес → 403) — админка переписывает провайдеров и `MAIN_BASE_URL`,
  открывать её сети = подарить перехват промптов и ключей; сознательное исключение —
  `ADMIN_ALLOW_LAN=true` в `.env` (в `hidden_admin_keys`, самой админкой не включается). Все «дорогие»
  роуты (ход/создание мира/suggest/vision/providers/память/лор/карточки/импорт/TTS/админка) стоят под
  rate-limit'ом — реестр `ratelimit.SCOPES`, вешается `Depends(guard_for(scope))`; факт наличия
  сторожит реестр-тест по зависимостям самого приложения.
- **Админка читается отдельным sqlite-соединением** (`backend/admin_settings.py::read_overrides`) — НЕ
  через db.py: `db._db()` вызывает `get_config()`, а рекурсия config→db вешает сервер
  (нереентерабельный Lock). Не ломать!
- Per-world переопределения — `worlds.provider_settings` (JSON
  `{kind: {id, base_url, api_key, model, enabled}}`), меняются через `POST /api/worlds/{id}/providers`;
  пустой api_key/base_url/model = «оставить как есть» (ключи маскируются).
- Резолв: `config.get_provider(kind, overrides)` → dict `{id, name, base_url, api_key, model, enabled,
  needs_key, needs_model}`; `resolve_world_providers(ws)` → все три. LLM/эмбеддинги/реранкер принимают
  `provider=` (`llm.complete/stream_chat`, `embeddings.embed_batch/rerank_results`). Эмбеддинговый
  провайдер и основной резолвятся раздельно (`summarize_and_compress`: сводку генерирует основной,
  индексирует эмбеддинговый).
- **Живость основной модели проверяется ОДНОЙ функцией**: `llm.probe(provider)` →
  `(up, needs_key, detail)`; `llm.check_available()` — её же обёртка. Критерий: «жив» = ответ < 500
  (401/403/404 — живой сервис), ключ всегда шлём в `Authorization`, `needs_key` отдельно отличает «не
  отвечает» от «требует ключ». При создании мира недоступная модель → **503**, мир не создаётся.
- Если эмбеддинги `none`/без ключа — `retrieve_memory` тихо возвращает пусто (RAG выключен, игра
  живёт). Реранкер `none` или `enabled:false` — гибрид BM25+косинус без облачного реранка.

### Озвучка (TTS, `backend/tts.py`)
- Провайдеры: **piper** — локальный (sherpa-onnx, голоса `ru_RU-ruslan/irina/dmitri/denis-medium`,
  скачиваются из релиза k2-fsa/sherpa-onnx tts-models, ~30–70 МБ, качество среднее); **kokoro** —
  локальный Kokoro-82M (~350 МБ, без русского, для en-миров); **edge** — ⭐ **стандарт/рекомендован**:
  облачный Microsoft Edge TTS (`edge-tts`, русские голоса ru-RU-DmitryNeural (муж., стандарт)/
  SvetlanaNeural, бесплатно, нужен интернет); **none**. Дефолты: провайдер `edge`, голос
  `ru-RU-DmitryNeural`. Edge требует явный знак в `rate` (`+0%`, а не `0%`) — нормируется в
  `tts._synth_edge`.
- Глобальные настройки — `.env`/админка (`TTS_ENABLED/PROVIDER/VOICE/RATE/AUTO_PLAY/CACHE_*`);
  per-world — `worlds.tts_settings` JSON {enabled, provider, voice, rate, auto_play},
  `POST /api/worlds/{id}/tts/settings`; пустые поля = «по умолчанию (глобально)».
- Синтез — **фоновый** (`tts.ensure_event_audio`, не блокирует ответ): событию рассказчика ставится
  `tts_status=1`, аудио кэшируется по хешу (текст+голос+скорость) в `data/tts/cache/` (+ таблица
  `tts_cache`); статус события 2=готово, −1=ошибка (повтор — `POST .../events/{eid}/tts/retry`).
  Озвучивается только `final_text` (без механики); `TTS_MAX_CHARS` (2400) режет текст по предложениям.
- UI: кнопка 🔊/⟳/⚠ у ответов рассказчика, поллинг готовности, авто-плей, «Проверить голос»/«Скачать
  голос» в настройках мира; глобально — админка.

### Автогенерация контента
- Создание мира: `generate_opening` — LLM пишет вступительную сцену по теме (с инжектом лора и
  вплетением персонажа).
- **Два разных лимита токенов (НЕ путать!):** `MAX_TOKENS` (в `.env`/админке/настройках мира,
  стандарт 2000) — лимит **КАЖДОГО обычного хода игры** (`routers/core.py::_gen_params` →
  `gen_settings.max_tokens`); `OPENING_MAX_TOKENS = 2400` в
  `backend/character_generator.py::generate_opening` (`narrator.py` — только реэкспорт фасада) —
  отдельный разовый вызов при создании мира, настроек мира **не читает**; 2400 — с запасом под
  reasoner-модели (часть лимита уходит на reasoning), там же `temperature = default_temp + 0.05`, до 3
  повторов при пустом ИЛИ оборванном вступлении и фолбэк на `theme.opening`. Настройка 2000 НЕ влияет
  на длину вступления, а 2400 НЕ влияют на игровые ответы.
- **Сюжеты-миры живут файлами в папке `plots/`** (НЕ хардкодом): `plots/system/` — комплектные
  «стандартные» сюжеты, `plots/user/` — сюжеты игрока. Каждый файл — чистый JSON (расширение `.js`) по
  полной схеме `PLOTS.md` (`metadata`/`lore_articles`/`lore_text`/`factions`/`starting_state`/`story`/
  `plot_text`/`handoff_directives`).
- **Загрузчик `backend/plots.py`**: при старте и по кнопке «🔄 Обновить сюжеты»
  (`POST /api/plots/reload`) сканирует обе папки, строит тему-обёртку для каждого сюжета и отдаёт в
  `narrator.THEMES`/каталог. `GET /api/themes` сам проверяет mtime файлов (`ensure_fresh`) — новый или
  правленый сюжет подтягивается даже без кнопки/рестарта. `id` темы = поле `id` файла или
  транслитерация имени файла; `user/` переопределяет `system/` при совпадении id.
- **При создании мира из сюжета** (`worlds.py::create_world`): тема-обёртка даёт стиль/жанр/завязку/
  лор; `narrator.apply_plot_start` применяет `starting_state` (локации/NPC/магазины/фракции/квесты/
  флаги/время/погода/золото/инвентарь). Роль игрока (раса/класс/статы/уровень) **не из сюжета** — её
  генерирует `generate_character` (PLOTS.md п.5.1).
- **Миры не зависят от файлов сюжетов**: при создании в `setting["_theme_snapshot"]` копируется
  тема-обёртка, а `narrator._world_theme(world, setting)` использует её как фолбэк, если файл сюжета
  позже удалён/отредактирован → мир живёт по данным на момент создания.
- **Автопроверка сюжетов**: новый/правленый файл сюжета обязательно прогонять через
  `scripts/check_plot.py plots/<folder>/<file>.js` — ловит призрачные id (relations/connections/
  key_quests/key_npcs/next_quest_id), дубли `new_locations` (локация уже в старте), `false`-флаги в
  `key_flags_to_set`, недопустимые статусы квестов/связей фракций, рассинхрон `lore_articles`↔
  `lore_text`. Правила закреплены в PLOTS.md (п.4.1/4.2/4.4/5.3/9/12).
- Подсказки жанров — `GENRE_HINTS` (33 шт) в `narrator_data.py`.
- Стиль тем/сюжетов (`plots._theme_from_plot`, `narrator.theme_from_custom`, фолбэк `_world_theme`):
  **канва — напряжение, а не маршрут** (не «строго в русле сюжета → вести к финалу по канве»), иначе
  стандартные сюжеты становятся рельсовыми; лор при этом остаётся законом.

## 🗄 СХЕМА БД (backend/db.py)

- `worlds(id, name, theme, genre, perspective, language, custom_hook, setting JSON, gen_settings JSON, narrator_id, provider_settings JSON, tts_settings JSON, snapshot TEXT, created_at, updated_at)` — `genre` может содержать **несколько жанров** через запятую (`POST /api/worlds {genres: [...]}`); `theme='custom'` = **свой сюжет** (`custom_plot` — текст / `plot_id` — сохранённый); `snapshot` — состояние до последнего хода для отката при перегенерации.
- `events(id, world_id, seq, role[narrator|player|system|dice|summary|divine], content, folded, feedback[-1|0|1], tts_status, tts_file, ts)` — полная история, индекс `(world_id, seq)`. `folded`: 0 видно / 1 свёрнуто в сводку / 2 сокрыто перемоткой. `tts_status`: 0 нет / 1 в работе / 2 готово / −1 ошибка.
- `saves(id, world_id, name, seq, setting JSON, created_at)` — слоты сохранений;
  `turn_snapshots(world_id, seq, setting, created_at)` — состояние ПЕРЕД ходом (точки ⏪, keep `TURN_SNAPSHOT_KEEP`).
- `lore(id, world_id, title, content, tags, is_core, source[theme|custom|user], created_at, updated_at)` — статьи лора (слой 6).
- `entities(id, world_id, kind[npc|location|faction|quest|item|event|race|class|profession|skill|effect|journal], entity_key, name, summary, relationship, bio, meta JSON, seq, created_at, updated_at, UNIQUE(world_id,kind,entity_key))` — карточки сущностей и знаний.
- `narrators(id, name UNIQUE, desc, prompt, is_preset, created_at, updated_at)` — рассказчики;
  `story_plots(id, name, plot, lore, created_at, updated_at)` — свои сюжеты («Свой сюжет» — первый пункт темы + «Мои сюжеты»); `lore` станет лором мира при создании.
- `tts_cache(id, text_hash UNIQUE, provider, voice, rate, fmt, rel_path, created_at)`;
  `admin_settings(key PK, value, updated_at)` — ключи в ВЕРХНЕМ регистре, как env.
- **Графовая БД**: `graph_nodes(world_id, node_id PK(world_id,node_id), label, kind[location/faction/shop/npc/quest/custom], data JSON)` и `graph_edges(world_id, source, target PK(world_id,source,target), weight, data JSON)` — персистентный граф карты и связей. Рёбра неориентированные, хранятся канонически (`source <= target`, без дублей). Источник истины — `setting.locations[].connections`; `graph.sync_from_setting` перестраивает граф атомарно (в транзакции хода и при создании), инкрементальный путь не трогает БД при неизменности. В граф входят не только локации, но и фракции/магазины/живые NPC; вкладка «Карта» и `/map` читают граф-эндпоинт.

> Миграции идемпотентны: `CREATE TABLE IF NOT EXISTS` + `_migrate_worlds` (PRAGMA → `ALTER TABLE ADD COLUMN narrator_id / provider_settings / snapshot`).

## 💻 СОГЛАШЕНИЯ ПО КОДУ

- Python: `from __future__ import annotations`, типизация, UTF-8.
- **SQLite — только через `backend/db.py` на aiosqlite**: единственное соединение живёт на выделенном
  фоновом asyncio-цикле (поток `aiosqlite-loop`), а публичный API модуля остался **синхронным** —
  каждая функция ставит корутину в очередь (`_run` + `run_coroutine_threadsafe`) и ждёт результат;
  `transaction()`/RLock/`_tx_depth` прежние. `_maybe_commit` — корутина (внутри корутин коммит
  напрямую `await conn.commit()`, а НЕ через `_run` — иначе дедлок на том же цикле). `db.close()`
  корректно закрывает соединение/цикл в тестах и скриптах. **Белый список полей записи**:
  `update_world(**fields)` пишет только колоночные имена (`name/setting/gen_settings/narrator_id/
  provider_settings/snapshot/tts_settings`) — это единственная защита от подстановки имени колонки в
  SQL; лишние ключи в `UPDATE` не попадают, но и молча не глотаются: на каждый лишний ключ —
  `log.warning("update_world(world N): неизвестное поле …")`, иначе опечатка в имени поля выглядела
  бы как «записали и ничего не случилось» (правило 14).
- **Разделение слоёв**: `db.py` — ЧИСТО доступ к данным (никакой бизнес/презентационной логики: без
  форматирования, без подписей ролей, без сборки текстов). Бизнес-логика — в `routers/*`, механика —
  `mechanics.py`, память/промпты — `narrator.py`. Нужен форматированный вывод (напр. экспорт) → `db`
  отдаёт сырые данные, а текст собирается в роутере (`db.export_data` →
  `routers/worlds.py::render_export_history`).
- **Атомарные группы записи**: `db.transaction()` — события хода + состояние мира одной транзакцией;
  `_lock` удерживается **на всё время тела**, поэтому тело ОБЯЗАНО быть синхронным (без `await`) —
  инвариант проверяет `tests/test_session38_layers.py::test_no_await_inside_transaction_body`.
  Мутации состояния хода (карточки знаний → дневник → ружья Чехова) идут ДО единой `update_world` в
  конце транзакции. **Таймаут внутри группы дозакрывает транзакцию сам (D12):** `_tx_depth`
  уменьшается ПЕРЕД `_run(_commit_now)`, поэтому при «БД не ответила за `_RUN_TIMEOUT`» отменённая
  корутина коммита оставляла единственное соединение в открытом `BEGIN IMMEDIATE` — строки откатанного
  хода оставались видны этому же соединению, буфер `_pending_events` уносился в шину живого чата
  следующим коммитом (фантомы), а файл держал write-lock. Теперь признак незакрытого BEGIN ведёт флаг
  `_tx_open`, и `_run` при таймауте с `_tx_open and _tx_depth == 0` зовёт `_rescue_transaction`
  (`log.error` с контекстом + явный `_rollback_now` + очистка буфера; отказ самого отката — тоже
  `log.error`; исключение таймаута не подменяется). Вне `transaction()` BEGIN не открыт, поэтому
  ложных откатов нет.
- **SSE streaming** в `backend/routers/worlds.py::action_stream`: worker кладёт токены в
  `asyncio.Queue`, генератор `gen_stream()` отдаёт `event: token` / `event: result` (один в конце) /
  `event: error`. Слэш-команды через стрим отдают **тот же** `event: result` (фронт слушает только
  token/result/error, `event: done` терял ответ команды). Колбэк стрима корутиновый:
  `await stream_emit(delta)` (забытый `await` = 0 токенов в стриме).
- **Перегенерация ↻ заменяет, а не копит**: in-memory реестр `routers/core.py::_turn_events`/
  `_turn_seq` — при регенерировании последнего хода события прошлого хода (narrator/dice/system)
  удаляются (`db.delete_events_by_id`) и создаются новые; фоновые события мира (динамические/судья) не
  затрагиваются. Результат `_process_action` возвращает `replaced_events` — фронт убирает старые
  `.msg` по id. После рестарта сервера реестр пуст → реген работает как append.
  Регрессия: `tests/test_api.py::test_regenerate_replaces_events`.
- **Мелочи, на которые наступали** (не изобретать заново): `.items()[:N]` бросает TypeError — всегда
  `list(...)[:N]`; Chroma c несколькими фильтрами требует `{"$and": [{…}, {…}]}` (один ключ — без
  `$and`); `bm25_scores` нужен локальный `doc_len` в цикле; `FRONTEND_DIR` =
  `Path(narrator.__file__).parent.parent / "frontend"`; `PROVIDER_OPTIONS` — константа модуля, не
  атрибут `Config`; в `summarize_and_compress` провайдер эмбеддингов и основной резолвятся раздельно;
  `db._add_event` на пустом тексте бросает `ValueError` (пустое вступление больше не роняет создание
  мира и не рождает пустое сообщение); при `↻` и при загрузке сохранения обязательно чистить векторы
  (`_purge_vectors`) и stale-сводки, иначе сводка «будущего» утекает в промпт; крафт — только с
  ингредиентами (пустой `ingredients` = отказ, «нет бесплатных предметов»), дублирующиеся
  ингредиенты с одним именем складываются в один `{name, qty}`.
- Токены оценивать `config.est_tokens` (len/3.2), не полагаться на точность.

### Инварианты (легко наступить снова — проверять при доработках)

1. **`meta.turn` — метка СОБЫТИЙ ХОДА** (= seq действия игрока). Новый агент/директива, пишущие
   события в ход, обязаны ставить метку, иначе `↻` их не заменит. Фоновые события мира метку НЕ носят.
2. **Фоновая запись в setting — только через `_bg_may_write(...)`** (ядро) или проверку
   `bg.is_regenerating()` (память), СРАЗУ после перечитывания состояния: `await` между чтением и
   записью = гонка; нельзя возвращаться к `s`/`world`, снятым в начале функции. `POST .../divine`
   сверяется тем же механизмом и пишет результат ПОВЕРХ перечитанного `fresh` (директивы Провидения
   применяются повторно к нему, а не к снимку начала запроса). Откат таймлайна (⏪ перемотка, загрузка
   сохранения) держит ТУ ЖЕ перемычку `_regen` через `bg.rewind_block`, а ход игрока занимает мир
   через `bg.turn_block` — без этого «перемотку» догоняет идущий ход и мир сразу уезжает в будущее.
   Занятый мир = честный 409, а не тихая порча прохождения.
3. **Синхронизация «карточки → setting»**: один распарсенный объект, одна запись в конце. Парсить
   `world["setting"]` по месту в каждом блоке нельзя — следующий блок затрёт предыдущий (проверено:
   терялись квесты и NPC).
4. **Состояние хода пишется ОДНИМ `update_world` ПОСЛЕ всех мутаций** (карточки знаний → дневник →
   ружья Чехова): мутация после записи теряется для следующего хода.
5. **Новый формат вывода модели в `split_engine`** добавляется в `_iter_json_objs` / `_is_engine_obj`,
   а не отдельным регэкспом; `ENGINE_KEYS` пополняется из `DIRECTIVE_CHAIN` сам (`roll`/`dice` — явно).
6. **`ensure_player_schema`** — единственная гарантия числовых осей игрока (`hp/mp/gold/level/
   inventory`): `apply_directives` читает `p["hp"]` напрямую. Молча чинить кривые данные вне схемы
   нельзя.
7. **`db._run` бросает `RuntimeError` из потока цикла БД**: фоновым корутинам на этом цикле нельзя
   вызывать синхронный API `db.*` (выполняй корутины `_*` напрямую или через очередь).
8. **`db.get_events_after` — вперёд по seq; `get_events(limit=N)` — ХВОСТ из N последних.** Страницы
   лога, SSE-догон и reindex используют первый.
9. **`_totals_baseline` в `metrics`** снимается ДО первой собственной записи процесса в журнал (иначе
   свои ходы попадут в счёт дважды). Буфер `_pending` — модульный глобал под `_pending_lock`: тестам
   его чистят `reset_buffer()`, а `flush()` обязан уметь работать и без активного цикла событий
   (скрипты, остановка сервера) — иначе последние метрики прохождения молча теряются.
10. **Ярусы промпта (`gated_rules`/`trim_prompt`) ключуются НОМЕРАМИ правил** → нумерация в
    `build_system_prompt` обязана быть стабильной: каждое правило — одной строкой и одним элементом
    списка. Из-за склейки без `\n` лор-блок (27–29) приклеивался к правилу 26, и в мире без фракций
    `trim_prompt` молча вырезал «библию вселенной». Правила 9/9а/16 не выкладываются даже без
    врагов/эффектов (риск задвоенного урона). `lore_rules` — НЕ f-строка (фигурные скобки одинарные).
    Хвост правил живёт в `narrator_data.TAIL_RULES` с базой `TAIL_RULE_BASE`, номера считает цикл, а
    тест `test_prompt_rules_numbering` сверяет последний номер с
    `TAIL_RULE_BASE + len(TAIL_RULES) - 1` — добавить правило «молча» нельзя. Правило 37 намеренно
    ОТСУТСТВУЕТ в `_GATED_RULES`: ярусы режут только правила мёртвых подсистем, а право рассказчика
    гнуть мир под игрока нужно каждому миру каждый ход.
11. **Лог мира = один предикат.** Сервер отдаёт `core.CHAT_LOG_ROLES`, фронт фильтрует через
    `shouldRenderEvent()`/`shouldRenderLive()`; сводки (`summary`) игроку не показываются нигде — это
    материал промпта. `/history` использует те же роли, иначе пагинация врёт.
12. **В тестах**: `LOG_FILE` = temp; `root.propagate=True` + `NullHandler` на корневом логгере (иначе
    `caplog` слепнет и правило 14 не проверить). Планировщик фона глобален, а цикл у каждого
    TestClient свой — фикстура `api_client` обязана звать `bg.reset()`.
13. **Форма админки шлёт только изменённые поля** (`dataset.orig` + `valOr`/`boolOr`): новое поле
    обязано заполняться через `setAg`/`setAgCheck`, иначе правка молча не сохранится. Любой дефолт
    `.env`/кода на живой базе перебивается ранее материализованной строкой в `admin_settings` — при
    «дефолт не применяется» смотреть туда / жать «Сбросить всё к .env».
14. **Единый реестр переопределяемых настроек** — `config.overridable_env_keys()` (производен от
    dataclass, устареть не может): его валидирует роутер (`reset` с неизвестным ключом → 400) и по
    нему фронт строит сброс. Что сознательно только в `.env` — `config.hidden_admin_keys()`
    (пути/порты, `LOG_FILE`). **Мёртвая настройка дороже опечатки**: `RERANK_TOP_N` пережил снятие
    ручки (A17) удвоенным — строкой в `.env` И осколком в `admin_settings`. Теперь `Config.load` пишет
    warning про КАЖДЫЙ ключ, которого нет в реестре (`_warn_dead_keys`, раздельно по источникам),
    `GET /api/admin/settings` отдаёт их в `stale`, а «Сбросить всё к .env» снимает и их. Новое поле
    Config обязано читаться кодом — следит `tests/test_session58_dead_config.py`; адрес/порт игры —
    зона launcher'а, не конфига.
15. **`.bat` не содержат абсолютных путей**: корень — `%~dp0..`, интерпретатор — `GAME_PYTHON`/`PY`
    из окружения → `python` из PATH. Health-check внешних сервисов — всегда по **коду ответа**
    (`< 500` = жив) и на том же эндпоинте, что спрашивает код. Файлы `.bat` обязаны оставаться CRLF.
15а. **В `.bat` внутри многострочного `if (...)` любая скобка в `echo`/`set` экранируется** —
    `^(текст^)`: cmd.exe закрывает блок по ПЕРВОЙ неэкранированной `)`, и строки после неё (часто это
    `pause` и `exit /b 0`) начинают выполняться безусловно. Так `start_game.bat` с сессии 33 **не
    запускал сервер никогда** — молча выходил с кодом 0 на ветке «игра уже запущена»; вскрыл это
    только исполняющий харнесс (`tests/test_start_bat_harness.py`), текст файла выглядел корректно.
    Сторожится поведением (`test_harness_detects_broken_block_echo`) и структурно
    (`check_start_bat.block_echo_check` — работает и на Linux, где cmd.exe нет). В кавычках
    (`echo "(x)"`) и вне блока скобки безвредны, чекер знает разницу.
15б. **Побочные эффекты launcher'а обязаны быть отключаемыми из окружения**: ветка «игра уже
    запущена» зовёт `start "" http://127.0.0.1:8002`, а `start` — внутренняя команда cmd, её не
    подменить файлом в PATH, поэтому автотест открывал бы браузер на рабочем столе. `start` обёрнут в
    guard `GAME_NO_BROWSER` (пусто по умолчанию — поведение игрока не меняется); харнесс ставит флаг и
    проверяет, что guard не снимут. То же к любому новому «удобству» в bat.
16. **`plots/*.js` — это JSON с расширением `.js`** (соглашение `PLOTS.md`): редакторная валидация и
    `node --check` на них не работают, поэтому структуру и ссылки проверяет `scripts/check_plot.py`
    (CI гоняет и `plots/user`), а битый файл не должен молча исчезать из каталога — он виден в
    `GET /api/themes` → `plots_errors` и плашкой в UI.
17. **`check_frontend.py`/`check_typos.py` глушат строку маркером `TYPO-OK`** (как noqa): он нужен,
    где документация ЦИТИРУЕТ исправленную опечатку/иероглиф. Тот же маркер глушит проверку C3
    (латиница, приклеенная к кириллице), а сам `scripts/check_typos.py` собирается так, чтобы
    проходить собственную проверку. ⚠ Граница метода: `GLUE_RE` срабатывает только на СЛИТНЫЙ стык
    двух алфавитов — со пробелом та же регулярка даёт 376 попаданий по одному `backend/`
    («через RAG», «в JSON»), т.е. нормальную техническую речь; такой сканер выключают.
18. **Тест на опциональной зависимости** (edge-tts / sherpa-onnx / fastembed) обязан защищаться
    `pytest.importorskip` — локально всё стоит, краснота вспыхивает только в CI.
19. **Тесты, сверяющие ТЕКСТ исходников/`.bat`** — smoke «правка на месте», а НЕ регрессия
    поведения: они падают при безвредном рефакторинге и проходят при реальной поломке. Новые проверки
    так писать нельзя — только поведение; структурные — в `scripts/check_*.py`.
20. **Весь текст из мира (LLM, директивы мастера, импорт дампа) идёт в разметку ТОЛЬКО через
    `esc()`/`trunc()`**; атрибуты — `attrArg()`, числа — `numAttr()`, путь URL —
    `encodeURIComponent()`. `trunc()` и `kv()` экранируют САМИ (повторно оборачивать их результат в
    `esc()` нельзя — игрок увидит `&lt;`); намеренный HTML в пары «метка→значение» — только через
    `kvHtml()`. Дырявые по умолчанию помощники были источником XSS: `<img src=x onerror=…>` в
    описании предмета выполнялся во вкладке игрока. Сторожится структурно
    (`check_frontend.xss_check`) и поведением (`xss_behavior_check` + `scripts/xss_probe.js`).
    Переводить вёрстку карточек на `textContent` нельзя — ломает разметку, экранируем значения.
21. **Категория карточки (`meta.$.cat`) фильтруется и считается в SQLite, а не в Python**: горячим
    путям (`journal.entries` / `entry_categories`) нельзя брать `db.list_entities()` без limit и резать
    `cat`/`limit` постфактум. Для этого `db.list_cards(world_id, kind, limit, cat)` и
    `db.count_cards_by_cat()`. Общий SQL-фрагмент `_CAT_SQL` обязан переживать `json_valid = 0`
    (битая meta в боевой базе реальна): карточка с нечитаемой meta считается категорией `world`, а не
    исчезает из дневника.
22. **Ни одна выборка лога не бывает «без лимита»**: у `GET /history` и `/events` есть потолок
    страницы (`db.HISTORY_PAGE_MAX`, `worlds._EVENTS_PAGE_LIMIT`). «Нет лимита» в URL = дефолтная
    страница, а НЕ весь лог мира. Ответ обязан нести честный `truncated` — иначе клиент ждёт
    молчания; лишняя строка вычитывается одним `LIMIT n+1`, без `COUNT` по всему логу. Размер
    страницы фронта (`app.js::LOG_PAGE_SIZE`) не может превышать серверный потолок. Фронт принимает и
    старый формат (голый список), новые клиенты обязаны читать объект.
23. **Любая числовая настройка игры имеет границы в одном месте** — `config.NUM_RANGES`. Раньше
    валидация была одна: «`int()`/`float()` упадёт → дефолт», поэтому `max_tokens: 0`,
    `temperature: 1e9`, `LLM_TIMEOUT=0.01` сохранялись как есть и ломали КАЖДЫЙ будущий ход.
    Применяется на всех путях: `Config.load`, `narrator.world_gen_settings` (пер-мир, ПРИ ЧТЕНИИ —
    кривой JSON мог прийти из старого сохранения или импортированного дампа),
    `routers/admin.py::_admin_num`, `logsetup._clamped_int_env`. Новая числовая настройка = запись в
    `NUM_RANGES` (реестр проверяет тест: имена — поля `Config`, дефолты попадают в границы). `0` у
    ключей из `NUM_ZERO_KEYS` — задокументированный РЕЖИМ (`TURN_SNAPSHOT_KEEP=0` = хранить все,
    `AUTO_TIME_EVERY=0` = часы выкл.). Подрезка всегда пишется в журнал, ответ `/settings` несёт
    `gen_limits` — тихой подмены значений игрока нет (законы 2/3).
24. **У логики карточек/дневника есть владелец — `backend/journal.py`, роутер только дергает его
    функцию**. `/journal note` построил `db.upsert_entity(...)` прямо в `routers/worlds.py`, и
    `add_player_note()` — единственный владелец ключа/лимита/иконки — не вызывался из приложения ни
    разу. Итог: два набора лимитов и мета-полей, правки в `journal.py` до чата не доходят, а тест
    владельца зелёный. Так же: `routers/entities.py` пишет карточки «сырых» сущностей — это его домен,
    а записи дневника (`kind="journal"`) обязаны рождаться только в `journal.py`.
25. **Живая лента обязана уметь сообщать, что лог УСТАРЕЛ, а не только что он вырос**. `bus.publish`
    нёс только `{"type":"event"}`, а вторая вкладка после ⏪/💾 держала удалённые ходы до F5. Теперь
    откат делает ДВА заявления: публикует в шину `{"type":"rewound", seq, mode, event_id, latest_seq}`
    ПОСЛЕ всех записей в БД и ставит метку `meta.rewound` на своей служебной строке. Метка обязательна:
    событие отката в `delete` имеет seq самой точки и через `?since=` к отсталому подписчику не доедет
    НИКОГДА, поэтому поллинг сверяет `latest_seq` с курсором `seenSeq`. Реакция фронта —
    `applyRewound`/`reloadWorld` (полный `openWorld`, а не «догони хвост») с флагом `state.reloading`.
26. **Никаких обращений к БД/диску/сети на импорте модуля**. Всё, что сервер делает при старте один раз
    (сид рассказчиков, бэкап БД, `prune_orphan_rows`, нормализация рангов, починка имён
    карточек/флагов/NPC + пересинхронизация карт, прогрев голосов TTS, `sweep_orphan_vectors`) —
    функция `app.self_heal()` (и аналоги) из `_lifespan` фоновой задачей (`bg.spawn`) с одной строкой
    журнала. На импорте эти же вызовы стоили второму экземпляру сервера `database is locked` с полным
    таймаутом `db._run` на каждой группе (замерено: 12.6 с против 0.3 с), а pytest/CI платили полную
    цену обхода всех миров. Исключения — только дешёвые чтения/свои таблицы: `_configure_logs()`,
    загрузчики `plots/` и `plots/narrators/` (читают файлы, не БД), `admin_settings.read_overrides()`.
    Если UI-эндпоинт не может работать без результата (как `GET /api/narrators` до фонового прохода) —
    нужна дешёвая lazily-страховка, а не возврат прохода на импорт.
27. **«Дорогой» эндпоинт не бывает без лимитера**. Любой роут, который зовёт LLM, облачные
    эмбеддинги/реранкер, синтез речи, скачивание моделей, полную переиндексацию памяти или меняет
    глобальные настройки, обязан висеть под `Depends(guard_for(scope))`, а имя scope — существовать в
    реестре `ratelimit.SCOPES` (свои значения на каждый роут, лимиты ЩЕДРЫЕ: цель — скрипт/заломанная
    кнопка/чужой в сети, а не игрок). У игры нет авторизации, а `GAME_BIND` может быть не loopback,
    поэтому чужому адресу лимиты режутся в `REMOTE_FACTOR` раз, а `/api/admin/settings` дополнительно
    закрыт до localhost. Новый роутер с guard'ом вешается меткой `_rl_scope` (ставит сам
    `guard_for`) — реестр-тест читает зависимости маршрутов приложения, поэтому молча забыть лимитер
    нельзя, как и выдуманный scope. Счётчики лимитера — обычные словари, а не `defaultdict`: чтение
    чужого ключа не создаёт запись, а неиспользуемые ключи выметает амортизированная `_prune()`.
    Тот же закон действует в `bus.py`: in-memory реестр «кто чем пользуется» обязан уметь и ТЕРЯТЬ
    пользователей.
28. **Ни одно пользовательское текстовое поле API не бывает без границы длины**. Границы живут одним
    местом — константы `backend/schemas.py` (`PERSONA_MAX`, `PLOT_MAX`, `LORE_TEXT_MAX`, `HOOK_MAX`,
    `COMPLAINT_MAX`, `ACTION_HARD_MAX`, `CARD_*`, `NAME_MAX`, …) в `Field(max_length=…)` — и числа
    берутся «с запасом над реальностью» (тест сверяет их с фактическими текстами). Причина не в
    «гигиене»: один POST с мегабайтным текстом раньше оседал в SQLite и уходил в промпт КАЖДОГО хода
    мира. Мягкий лимит действия игрока остаётся в админке (`max_action_chars` → 400 с человеческим
    текстом), а схема обязана пускать больше (`ACTION_HARD_MAX` — жёсткий потолок тела). Персона,
    которая уже лежит в базе (старый мир, импорт дампа, правка файла пресета), не может раздуть
    промпт: `narrator.clip_persona`/`PERSONA_TOKEN_BUDGET` режут её при сборке system-промпта (ярусы
    промпта персоны не жертвуют — она идёт первой строкой); лор же в жертвенной секции и отдаётся при
    переборе окна ПЕРВЫМ. Отказ — 422 с человекочитаемым `detail` (в `app.py` висит обработчик
    `RequestValidationError`: фронт читает `detail` как текст, а pydantic отдаёт список объектов) и
    `log.warning`. Новое текстовое поле схемы = `Field(max_length=…)`, а не «как-нибудь порежем в
    роутере».
29. **Док не имеет права заявлять, что рабочее дерево чисто**. `nul` и `server*.log` — не «удалённый
    навсегда мусор», а штатные побочные эффекты запуска: они МОГУТ лежать в корне рабочей копии, и
    это не ошибка. Граница одна — индекс git (правило 15), а правдивость формулировки сторожит
    `tests/test_session57_worktree_trash.py`: канон мусора покрыт `.gitignore` и живые разделы правил
    не обещают навечно убранный мусор без оговорок. Удалять такие файлы — только по явному
    разрешению владельца.
30. **Повторяющееся число в документах живёт в реестре, а не в руках**. Число pytest-тестов /
    рассказчиков / сюжетов / жанровых подсказок / путей и операций OpenAPI заявлено в README, AGENT и
    ROADMAP в нескольких строках, и ручная синхронизация была тем, что каждая сессия забывала (ROADMAP
    жил с «534», AGENT говорил одновременно «795» и «388» — файл врал сам себе). Теперь у таких чисел
    ОДИН владелец — `scripts/doc_figures.py`: реестр `FIGURES` (чем мерить ↔ где заявлено) +
    `--check` + `--sync` (переписывает число и падеж во всех живых разделах). Добавил тест — не ищи
    глазами цифру, гони `--sync`; заявление обязано находиться РОВНО один раз (перенёс строку — поправь
    якорь в реестре). ИСТОРИЧЕСКИЕ сводки сессий под сверку НЕ заносятся: править отчёт прошедшей
    сессии = фальсификация. Нельзя измерить — в реестр не пишем (длительность прогона, размеры КБ).
    О ЧИСЛЕ мало: таблица API README обязана ПЕРЕЧИСЛЯТЬ все пути схемы, а таблицы README/AGENT — не
    обещать того, чего в приложении уже нет (`test_session60_openapi_documented.py`).
31. **У векторной памяти есть обратная сверка с БД**. Chroma — ВТОРОЙ склад тех же событий, что и
    SQLite, и раньше синхронность никто не сверял: векторы миров, стёртых прямым SQL или осиротевших
    после отката на бэкап, оставались НАВСЕГДА (замер на боевой базе: 55 разных `world_id` в векторах
    при 35 живых мирах — 23 мёртвых держали 160 чужих записей, и RAG доставал сюжет удалённого мира).
    Владелец вектора — `metadata.world_id` (запасной путь — префикс id: `ex_19_5`, `sum_4_2`,
    `ent_21_npc_herbalist`, `lore_7_3_0`), обход — постраничный `chroma_client.get_ids_by_world()`
    (короткая страница = конец, `max_pages` — потолок от бесконечного цикла). Чистит
    `memory.sweep_orphan_vectors()` (тот же образец, что `prune_orphan_rows`: идемпотентно, молчит на
    чистых данных, при недоступной Chroma — warning и пропуск) и зовётся из `_startup_heal`
    (правило 26). ТРОГАЕТ ТОЛЬКО ВЕКТОРЫ: законы 2/3 не нарушает, вектор, чей мир не опознан, НЕ
    удаляется — лучше осиротевший вектор, чем стёртый живой. Счётчик последнего прохода —
    `effective.vector_memory` в `/api/admin/settings` (НЕ отдельный роут: обход коллекции дорогой, а
    новый «дорогой» эндпоинт обязан попасть в реестр лимитов — правило 27). Индексация новых видов
    векторов без читаемого `world_id` делает сводку слепой.

| Добавить тему/мир | положить JSON-файл сюжета (схема из `PLOTS.md`) в `plots/user/` (или `plots/system/`) → в UI «Новый мир» нажать «🔄 Обновить сюжеты» (или перезагрузить страницу). id — из поля `id` или из имени файла; `user/` переопределяет `system/` |
| Добавить пресет рассказчика | положить JSON `{name, desc, prompt}` в `plots/narrators/` (имя вида `имя-рассказчика.js`) → перезагрузить страницу / `GET /api/narrators` (движок сам перечитает и пересидит в БД идемпотентно) |
| Привязать рассказчика к сюжету | в JSON сюжета поле `"narrator": "Имя пресета"` — при выборе сюжета он подставится в селект; игрок может сменить |
| Новый провайдер | опция в `config.py::PROVIDER_OPTIONS[kind]` + ветка резолва в `Config.get_provider` (+ ключи `.env` при надобности) |
| Новая директива механики | новый `DirectiveHandler` в `backend/mechanics.py` (класс с `keys` + метод `apply`) + добавление в `DIRECTIVE_CHAIN` + описание в `build_system_prompt`/`GAME_ENGINE_TOOL` + схема в `directives.py` (опц. парсер) |
| Механика vs память/промпты | механика директив и RPG-справочники — `backend/mechanics.py`; промпты, память, RAG, темы/рассказчики — `narrator.py` (+`memory.py`); у роутеров публичное API `narrator.apply_directives/normalize_directives/tick_effects` пробрасывается из механики |
| Новый эндпоинт | `backend/routers/<домен>.py` (app.py — только сборка) + схема в `backend/schemas.py` + JS-кнопка в `app.js` + строка в README «🗂 API» + (если «дорогой») scope в `ratelimit.SCOPES` (инварианты 27, 30) |
| Новая числовая/строковая настройка | поле `Config` + запись в `NUM_RANGES` (или константа в `schemas.py`) + ключ в `.env.example`; иначе она «мёртвая» (инварианты 14, 23, 28) |
| Персонаж/локация не забываются | уже автоматически: LLM-архивариус ведёт карточки после каждого хода |
| Модель «забывает» контекст | уменьшить `context_tokens`/бюджеты в `.env` (для llama.cpp n_ctx 8192!) или улучшить `summarize_and_compress` |
| Сброс памяти мира | удалить чанки Chroma по `world_id` (см. `chroma_client.delete_by_where`) |
| Закрыть сессию | ритуал из «🔄 РИТУАЛ ЗАКРЫТИЯ СЕССИИ»: отчёт в `AGENT_ARCHIVE.md` + одна строка правила сюда + `doc_figures --sync` |
